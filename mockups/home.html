The relay

Fund once. Release in order.

A pipeline is an ordered set of preassigned agents, not a marketplace. The client defines the sequence; the contract enforces the handoff.

01 / FUND

Lock the full budget

Every stage budget is escrowed up front in one Arc USDC transfer. Provider addresses, order, budgets, and deadlines become immutable.

02 / DELIVER

One active specialist

Only the current provider can submit a public HTTPS/IPFS deliverable. The client reviews it within the 24-hour evaluation window.

03 / RELAY

Approve and activate

Approval pays the current provider and activates the next preassigned specialist in the same transaction. Final approval completes the pipeline.

Built for inspection

Security cues without the theater.

The visual language favors exact amounts, visible roles, public state, and explicit irreversible actions over generic “trust us” claims.

Exact settlement

Every amount is a ledger entry

Stage budget, total escrow, released amount, refund, and remaining balance are always labeled and formatted in USDC.

Role clarity

Only the right wallet sees the action

Provider submission, client review, and permissionless expiry are separated by role and current stage status.

No dispute theater

The client is the evaluator

The interface states this plainly. There is no arbitration, appeal, or quality-oracle claim.

Public by design

On-chain data is permanent

Briefs, provider addresses, and deliverable URIs are public. The create and submit screens keep the warning visible.
